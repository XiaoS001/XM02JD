# XM02JD 总体计划与实施方案

> 定位：**岗位 JD 与 HR 提问驱动的技能补强项目**
> 技术栈：延续 XM01（JDK 8 + Spring Boot + MySQL 8 + Vue 3）
> 制定日期：2026-10-26　版本：v1.0
> 依据：`03-过程管理/01-经验库/XM01经验继承与避坑清单.md`、XM01 六步法

---

## 第一部分　总目标

### 1.1 一句话目标

> 把「收集到的岗位信息 + HR 提问」逐条转化为**可运行、可验证、可复述**的练手项目，形成求职证据链。

### 1.2 最终产出（四件套）

| 序号 | 产出 | 验收口径 |
|---|---|---|
| E1 | 技能差距分析 | 覆盖全部已录入 JD 的技能点，每条有差距评级与优先级 |
| E2 | 练手项目集 | 每个 🔴/🟡 差距对应一个**能跑起来**的项目 |
| E3 | 验证记录 | 每个项目有可复现的验证命令与输出摘要 |
| E4 | 面试话术库 | HR 提问台账里每条问题都有"有项目支撑"的答案 |

### 1.3 必须守住的三条线

1. **真实线**：做过的才写，没做过就补做。**绝不编造项目经历**（面试官一追问就穿帮）。
2. **验证线**：每个项目必须有机器验证记录，不能只写代码不验证。
3. **复述线**：每个项目都要能回答「做了什么 → 代码在哪 → 怎么验证 → 踩过什么坑」。

## 第二部分　工作流（核心机制）

```
① 采集   收集岗位 JD 与 HR 提问 → 原文录入 01-岗位与提问/
② 解析   提取技能点，对照现状标注差距等级（🔴/🟡/🟢）
③ 排序   按「出现岗位数 × 差距 × 实现成本」排优先级
④ 设计   为每个差距设计最小可运行练手项目 → 02-项目索引/
⑤ 实现   写代码 → 03-源码/
⑥ 验证   跑验证脚本，落盘验证记录 → 03-验证与实验/
⑦ 结项   写结项说明：目标/技术/代码位置/验证结果/踩坑
⑧ 复述   补充面试话术，回答 HR 提问台账里对应问题
```

**关键约束**：**④→⑧ 必须闭环**。只写代码不写结项说明 = 没完成；只写文档不写代码 = 没完成。

## 第三部分　阶段计划

> 不设固定日期（取决于素材录入速度），用**阶段门禁**推进：上阶段验证通过才进下阶段。

| 阶段 | 主要任务 | 产出物 | 完成标准 |
|---|---|---|---|
| **S0 框架搭建** | 目录结构、规范文档、模板 | Readme、计划、看板、经验库、三份模板 | 目录齐全，文档无占位符残留 ✅ |
| **S1 素材录入** | 录入岗位 JD 与 HR 提问 | `01-求职工作台/01-岗位与提问/` 下的实例文件 | 至少 1 份 JD + 5 条提问 |
| **S2 差距分析** | 提取技能点、评级、排序 | `技能差距分析.md` 填充完毕 | 每条技能点有差距等级与优先级 |
| **S3 项目设计** | 为 P0/P1 差距设计练手项目 | `01-求职工作台/02-项目索引/*.md` | 每个项目有明确验收标准 |
| **S4 项目实现** | 逐个实现并验证 | `01-求职工作台/03-源码/` + 验证记录 | 六步法逐项通过 |
| **S5 话术整理** | 补全 HR 提问答案 | `HR提问台账.md` 全部 ✅ | 每条答案有项目支撑 |

**推进纪律**：**一次只推进一个项目**，完成一个（含验证与结项）再开下一个。

## 第四部分　练手项目设计规范

### 4.1 项目编号与命名

`P<序号>-<技能点>-<简称>`，例：`P01-Redis缓存入门`、`P02-消息队列削峰`

### 4.2 每个项目的设计必须包含（模板见 `01-求职工作台/02-项目索引/_模板-练手项目.md`）

| 项 | 说明 |
|---|---|
| 对应 JD 要求 | 从哪条岗位要求来的（可追溯） |
| 目标 | 一句话说清要证明什么能力 |
| 技术方案 | 用什么技术、为什么（含方案对比） |
| 验收标准 | **可机器验证**的标准，不能是"了解了" |
| 验证方法 | 具体命令 / 测试用例 |
| 预估工作量 | 控制在能快速闭环（建议 ≤ 半天） |
| 面试话术要点 | 做完后能怎么讲 |

### 4.3 项目粒度原则

- **最小可运行**：能跑起来证明核心能力即可，不做大而全
- **有明确验收**：必须能"跑出一条命令看到结果"
- **能讲清原理**：做完能说出底层机制，不只是会用

## 第五部分　风险识别与应对

> 每条含：**现象 → 预案 → 触发条件**。排序按严重程度。

### R1　素材不足导致无法推进 ★致命

- **现象**：`01-求职工作台/01-岗位与提问/` 长期为空，差距分析无输入
- **预案**：
  1. 先按 XM01 已有技术栈（Java 后端 + 算法）补充**通用高频技能点**（Redis、MQ、Docker、并发）
  2. 从公开渠道（招聘网站、面经）收集典型 JD 与高频提问
  3. **与用户确认方向**后再扩大范围，不擅自假设
- **触发条件**：S1 阶段停顿超过一轮会话

### R2　环境阻塞 ★高（本会话已发生）

- **现象**：`pwsh` 工具报 `0xC0000142`，无法执行命令行
- **根因**：PowerShell 7 已装但 **DSH 进程未重启**，未加载新 PATH（见经验库 P1）
- **预案**：
  1. **立即绕行**：用文件工具 + Node.js / Python 直接执行，不卡在 `pwsh` 上
  2. 需要正式命令行的场景，重启 DSH 恢复
  3. 绝不因为环境问题停下推进
- **触发条件**：`pwsh` 调用返回 `0xC0000142`（已触发，已绕行）

### R3　项目范围蔓延 ★中

- **现象**：一个练手项目越做越大，想加的功能越来越多
- **预案**：
  1. 回到当初定的**验收标准**，达标即结项
  2. 新想法记入「加分项待办」，**不在本项目做**
  3. 严守"最小可运行"粒度原则
- **触发条件**：单个项目超过预估工作量 1 倍

### R4　只写代码不写结项 → 面试讲不出来 ★中

- **现象**：代码能跑，但被问"你做了什么"说不清楚
- **预案**：
  1. 结项说明是**必做项**，不是可选
  2. 按"做了什么 → 代码在哪 → 怎么验证 → 踩过什么坑"四问检查
  3. 写完结项说明后，**对着它口头讲一遍**，讲不顺就补
- **触发条件**：项目标记完成但没有结项说明

### R5　中文/编码问题导致返工 ★中

- **现象**：脚本中文乱码、`.ps1` 语法报错、`.cmd` 注释被当命令
- **预案**：严格执行经验库的 10 条铁律（`.ps1` 带 BOM、`.cmd` 存 GBK、中文落盘再读）
- **触发条件**：出现乱码或脚本语法错误

### R6　项目真实性被质疑 ★中

- **现象**：面试官追问细节答不上来
- **预案**：
  1. 只写自己真做过的
  2. 每个项目保留**完整提交记录与验证输出**作为佐证
  3. 没做过的坦承"没做过"，并说明"我为此做了什么准备"
- **触发条件**：任何项目无法回答"代码在哪、怎么验证的"

## 第六部分　执行方式（六步法，继承 XM01）

```
① 明确本步目标与验收标准
② 只做一件事，改动范围写清楚
③ 执行（写代码 / 写文档）
④ 立即验证（能编译的编译、能跑的跑、文档跑结构检查）
⑤ 记录到进度看板（做了什么、验证结果、遗留问题）
⑥ 验证通过才进入下一步
```

**核心纪律：一次只推进一件事；每步必须有一次机器验证。**

### 验证手段对照表

| 产出类型 | 验证方式 |
|---|---|
| Java 代码 | `mvn -q compile` 通过；接口用 curl 实测 |
| 前端代码 | `npm run build` 通过 |
| SQL 脚本 | MySQL 实际执行，核对表数/数据 |
| 算法/业务逻辑 | 单元测试 + **边界与合法性自检**（经验库 P9） |
| Redis / MQ 等中间件 | 实际读写、并发压测，输出落盘 |
| 配置修改 | **读回校验**（经验库 P4） |
| Markdown 文档 | 结构自检（章节完整、无占位符） |
