## 一、环境与工具类（★最高频，先看这三条）

### P1　`pwsh` 报 `0xC0000142` ★根因最有价值

| 项 | 内容 |
|---|---|
| **现象** | `pwsh` 工具执行任何命令都返回退出码 `3221225794`（十六进制 `0xC0000142` = `STATUS_DLL_INIT_FAILED`），无任何输出 |
| **初期误判** | 以为工作区 ACL 权限有问题，怀疑沙箱无法启动子进程 |
| **真正根因** | 本机**从未安装 PowerShell 7**。工具名 `pwsh` 指向的可执行文件不存在，启动失败被报成 DLL 初始化失败 |
| **反证** | `powershell.exe`（5.1）和 `cmd /c` 都能正常工作 |
| **XM01 解法** | 装 PowerShell 7.6.6 LTS |
| **XM02JD 现状** | `pwsh.exe` **已确认存在**于 `C:\Program Files\PowerShell\7\`（301368 字节），但本会话**所有子进程**仍报同样错误 → **根因修正见下方，不是 PATH 问题** |

**铁律**：`0xC0000142` 可能是"缺 DLL"、可能是"**可执行文件根本不存在**"、也可能是"**沙箱阻断了进程创建**"。
下次遇到先做**穷举对照**：换几个不同程序试 + 确认文件是否存在，再下结论。

### ★本会话根因修正（2026-10-26 实测）

本会话实测：`cmd.exe`、`powershell.exe`、`pwsh.exe`、`node.exe`、`java.exe`、`python.exe`
**六个程序全部返回 `0xC0000142`**，而用 `fs.stat` 逐个确认它们**全部都存在**。

→ **不是"pwsh 未安装"**（那是 XM01 当时的真实原因），
→ 而是**沙箱在部分受限模式下统一阻断了子进程创建**。

**判断法则**：
- 只有一个程序失败 → 查该程序本身
- **所有程序都失败 → 查沙箱 / 宿主运行模式**

详见同目录 `本机子进程启动失败问题-P1根因修正.md`（含完整可复现排查过程）。

**最终结论（2026-10-26 已闭环）**：根因是 DSH Windows ACL 沙箱的受限令牌（WRITE_RESTRICTED + Low 完整性）。
已排除 WorkBuddy 插件、PTC 模式、缺程序、PATH、空环境变量。
**解决**：会话沙箱切到「完全权限」（danger-full-access）即恢复。
**复发预警**：新开会话若默认回到 workspace-write，`0xC0000142` 会再出现，先查沙箱模式而非模型/插件。
详见同目录 `本机子进程启动失败问题-P1根因修正.md`。

### P3　中文输出乱码（★必守）

| 项 | 内容 |
|---|---|
| **现象** | `python-docx` 读出的中文经控制台回显全是乱码（如 `ʵ��Ŀ��`） |
| **根因** | Windows 控制台代码页（GBK）与 Python 输出的 UTF-8 不匹配，输出被二次错误解码 |
| **解法** | 脚本改为**把结果写入 UTF-8 文件**，再用文件读取工具读 —— 彻底绕开控制台编码 |

**XM02JD 铁律**：**任何处理中文的脚本，一律"落盘 + 读文件"，绝不依赖控制台回显。**

对应可运行示例见 `01-求职工作台/03-验证与实验/01-验证记录/` 的落盘脚本。

## 二、脚本编码类（★写脚本前必看）

### P7　`.ps1` 中文乱码导致语法错误

| 项 | 内容 |
|---|---|
| **现象** | `status-mysql.ps1` 报 `Unexpected token 'mysqld'`，中文显示为 `mysqld 鏈繍琛屻€?` |
| **根因** | Windows PowerShell 5.1 对**无 BOM 的 UTF-8** 脚本按 ANSI（GBK）解析，中文字节被错误解码后**破坏了引号配对** |
| **解法** | 统一给工作区所有 `.ps1` 加 **UTF-8 BOM** |

**XM02JD 铁律**：给这台机器写 `.ps1` **必须带 UTF-8 BOM**。

### P8　`.cmd` 中文乱码

| 项 | 内容 |
|---|---|
| **现象** | `mvn.cmd` 的中文注释被 cmd.exe 解析成命令，报 `'脚本（不依赖当前窗口的' is not recognized` |
| **根因** | cmd.exe 按系统 ANSI（GBK）读取批处理；文件却是 UTF-8 |
| **解法** | ① 项目内 `.cmd` 转为 **GBK**；② 另在**纯英文路径**放 ASCII 版包装脚本供自动化调用 |

**XM02JD 铁律**：`.cmd` 存 **GBK**；含中文路径会干扰编码，自动化脚本优先放**纯英文路径**。

## 三、配置与数据类

### P4　改配置只信日志 = 出事

| 项 | 内容 |
|---|---|
| **现象** | 脚本日志显示 `settings.xml patched`，但检查发现配置**没生效** |
| **根因** | 用正则 `</settings>` 定位插入点，却命中了**注释里的 `</mirrors>`**，配置被插进注释块 |
| **解法** | 改用 XML API 精确操作，并在写入后**重新解析校验**（确认 mirror 条目存在） |
| **附带发现** | PowerShell 的 XML DOM 调用在本机异常（`CreateElement('mirrors')` 返回 `null`），最终改用 **Python** 生成配置 |

**XM02JD 铁律**：**改配置文件后必须读回校验**，不能只看日志说"成功"。涉及 XML/JSON 生成优先用 Python。

### P5　命令行参数顺序错误导致全部失败

| 项 | 内容 |
|---|---|
| **现象** | `Access denied for user '-pWms@2026Root'@'localhost'` —— 用户名里居然带了密码 |
| **根因** | `cmd.insert(2, "-p"+pwd)` 把密码参数插到了 `-u` 之前，mysql 客户端把 `-pWms@2026Root` 当成了**用户名** |
| **解法** | 按正确顺序构造：`mysql -u USER -pPWD --port=... -e SQL`；补跑并做建表/插入/查询/删除冒烟测试 |

**XM02JD 铁律**：拼接命令行参数时，**参数顺序要显式核对**；DB 操作后做冒烟测试（建表→插入→查询→删除）。

## 四、代码正确性类（★最重要，直接决定数据可信度）

### P9　不做自检就会带着错数据走 ★

XM01 的自检脚本抓到**两个真实缺陷**，如果不做自检就会把错数据写进论文：

**缺陷 1：`abc_greedy` 溢出逻辑错误**
- 现象：`ValueError: shape mismatch: value array of shape (70,) could not be broadcast to indexing result of shape (127,)`
- 根因：某类商品数超过中区容量时，溢出处理用固定切区，导致容量不匹配
- 修复：改为**逐类占用"剩余最近货位"**，天然处理溢出

**缺陷 2：S 型与最大间隙策略漏记拣货点**
- 现象：路线只包含巷道折返点，**没有经过巷道内的拣货点**，导致距离偏小、对比失真
- 根因：把策略抽象成了"只记折返点"，但距离计算与合法性校验要求路线**包含全部拣货点**
- 修复：重写两个策略，路线按真实经过顺序包含全部拣货点并去重；新增自检项"**路线必须覆盖所有拣货点**"

**XM02JD 铁律**：
1. 任何算法/业务逻辑都要有**自检脚本**，不能只看"能跑出数"；
2. **结果的合法性必须显式校验**（覆盖完整、边界正确、约束满足），否则算出来的数字没有意义；
3. 自检通过才算完成 —— 这与六步法的"每步必须有一次机器验证"一致。

## 五、下载与网络类（低优先级，备查）

| 问题 | 根因 | 解法 |

**XM02JD 铁律**：下载大文件用**流式 + 国内镜像**；网络操作优先 Python，避开 PowerShell 5.1 的坑。

## 六、流程纪律类（继承 XM01 六步法）

XM01 确立并验证有效的开发纪律，XM02JD 直接沿用：

```
① 明确本步目标与验收标准
② 只做一件事，改动范围写清楚
③ 执行（写代码 / 写文档）
④ 立即验证（能编译的编译、能跑的跑、文档跑结构检查）
⑤ 记录到进度看板（做了什么、验证结果、遗留问题）
⑥ 验证通过才进入下一步
```

**核心**：**一次只推进一件事；每步必须有一次机器验证。**

### 验证手段对照表

| 产出类型 | 验证方式 |
|---|---|
| Java 代码 | `mvn -q compile` 编译通过；接口用 curl 实测 |
| 前端代码 | `npm run build` 构建通过；页面手工点一遍 |
| SQL 脚本 | 在 MySQL 中实际执行，`SHOW TABLES` 数量核对 |
| 算法代码 | 单元测试 + 小规模算例与穷举最优解对拍 |
| 配置修改 | **读回校验**（P4） |
| Markdown 文档 | 结构自检（章节完整性、无占位符残留） |
