# 本机子进程启动失败问题（0xC0000142）—— 已查明并解决

> 记录日期：2026-10-26
> 状态：✅ **已解决**（会话沙箱切到完全权限后全部恢复）
> 性质：**高**（在 workspace-write 模式下阻塞一切命令行执行）
> 结论：根因是 DSH Windows ACL 沙箱，与模型 / 插件 / PTC 模式无关

---

## 一、现象

在 `workspace-write` 沙箱模式下，**任何方式启动子进程都失败**：

| 启动方式 | 结果 |
|---|---|
| DSH `pwsh` 工具 | 退出码 `3221225794`（`0xC0000142` = STATUS_DLL_INIT_FAILED），无输出 |
| Node `spawn`（cmd / powershell / pwsh / node / java / python） | 全部同上 |
| 写工作区外文件 | EPERM 拒绝（沙箱文件层仍在生效） |

**stderr 为空**，进程直接以 `0xC0000142` 退出。

---

## 二、★最终根因（已闭环，非推断）

### 2.1 机制（读 DSH 源码确认）

`@deepseek-ai/dsh-sandbox-windows-acl` 在 `workspace-write` 模式下：

1. 把当前令牌复制成 **WRITE_RESTRICTED 受限令牌**；
2. 丢弃 `Authenticated Users`、`INTERACTIVE`、`LOCAL` 组；
3. 降到 **Low 完整性级别**（Mandatory Label）；
4. 用这个受限令牌启动子进程。

本机在该受限令牌下，子进程 DLL 初始化失败 → `0xC0000142`。

### 2.2 决定性证据：同一台机器、同一批文件，开关对照

| 沙箱模式 | 子进程 | 写工作区外 |
|---|---|---|
| workspace-write | ❌ 全挂 `0xC0000142` | ❌ EPERM |
| **danger-full-access** | ✅ cmd/pwsh/java/mvn/node/python/mysql 全通 | ✅ 放行 |

**命令能否执行，只与沙箱模式相关。**

### 2.3 一个容易误读的字段

DSH 一直回传 `enforcement: partial`。查源码 `STATIC_ENFORCEMENT` 表：

```
bwrap: "full", landlock: "full", seatbelt: "full", "windows-acl": "partial"
```

**`partial` 是 Windows 后端的固定静态标签，属于正常值，不是故障信号**。早先把它当成异常线索是误读。

---

## 三、排除掉的其他假设（都有证据）

| 假设 | 判定 | 证据 |
|---|---|---|
| WorkBuddy 插件 | ❌ 排除 | `dsh-workbuddy-connect` 只是模型供应商桥（hy3/hy4 等模型 ID），不接触沙箱 |
| PTC 会话模式 | ❌ 排除 | 沙箱源码不读 `agentPreset`；且本会话就是 PTC 模式，切 full 后命令照跑 |
| PowerShell 7 未装 | ❌ 排除 | pwsh.exe 存在（301368 字节）且切 full 后输出 7.6.6 |
| 缺程序 / PATH | ❌ 排除 | 所有可执行文件都存在，六程序全挂 |
| 环境变量为空 | ❌ 排除 | 手动补全 SystemRoot/PATH 后仍失败 |

---

## 四、为什么 XM01 "正常"

查会话档案 `session_projcache`：

| 会话 | 工作区 | preset | 沙箱 |
|---|---|---|---|
| a336f25f（XM01 主力） | XM01 | standard | **danger-full-access** |
| d8f1a1b8 / 3319e7ac | XM02JD | standard / ptc | workspace-write |

XM01 能干那么多活（167 次 pwsh 全成功），是因为**它的主力会话一直开在完全权限**。XM01 早期 workspace-write 会话的时间线为空，无证据价值——但 XM01 环境审计里把"PowerShell 7 未装"当主因，很可能是当时没识别出真正原因是沙箱。

---

## 五、解决方式

1. 把会话沙箱从 `workspace-write` 切到 `danger-full-access`（完全权限）→ 沙箱 provider 被跳过，子进程正常。
2. 本会话随即验证：cmd / pwsh / java / mvn / node / python / mysql 全通，MySQL 实例已启动，`wms` 库可连。

---

## 六、复发预警（重要）

**这个状态不是永久的，按会话记忆。**

- 下次**新开会话**若默认回到 `workspace-write`，`0xC0000142` 会再次出现。
- 届时**先看会话沙箱模式**，切到「完全权限」即可，不要怀疑模型 / 插件 / PTC 模式。

---

## 七、经验沉淀

1. 遇到 `0xC0000142`：**穷举对照**（换多个程序 + 确认文件是否存在 + 换沙箱模式），再下结论。
   - 只有一个程序失败 → 查该程序；
   - 所有程序都失败 → 查沙箱 / 宿主运行模式。
2. `enforcement: partial` 在 Windows 上 ≠ 出错，是静态标签。
3. 命令行启动常驻进程（如 mysqld）要 **detached**，否则会随启动它的进程一起退出。
