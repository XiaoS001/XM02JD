# P03 · LLM API 集成 + RAG 问答最小应用

> 立项：2026-10-14　状态：🔄 进行中
> 对应岗位线：AI 应用开发（补"API 集成 + RAG"缺口）
> 目标：做一个能跑的 RAG 问答应用，证明"会用 LLM API + 懂 RAG 原理"

## 一句话目标
用 Python 从 0 实现一个 RAG（检索增强生成）问答系统：文档→切分→向量化→检索→生成，全链路可跑、可验证。

## 技术决策（无外网 LLM API 的降级方案）
- **向量检索**：用 numpy 实现余弦相似度（不依赖外部向量库，符合"能不用第三方就不用"）
- **文档切分**：自写分块逻辑
- **LLM 调用**：预留 OpenAI/DeepSeek 兼容的 API 调用接口（可配置 key），**无 key 时降级为"检索结果拼接"模式**，保证离线可跑
- **演示语料**：内置一篇"AI 应用开发岗位"知识文档，问答能检索到相关内容

## 模块与验收标准
| 模块 | 做什么 | 验收标准 |
|---|---|---|
| M1 文档加载+切分 | 读入知识文档，切成块 | 输出 N 个块，每块有边界 |
| M2 向量化+检索 | 文本转向量，余弦相似度检索 | 给定问题能返回最相关块，相似度排序正确 |
| M3 生成 | LLM 调用 or 降级拼接 | 生成回答，含引用来源 |
| M4 评估 | 检索命中率自检 | 已知问题能命中正确块 |

## 面试一句话
"我用 Python 从 0 搭了个 RAG 问答：文档切块→向量化→余弦检索→生成。没依赖现成框架，所以能讲清每一步原理；LLM 接口留了 OpenAI 兼容的配置，没 key 也能离线跑通检索链路。"


## 踩坑记录（边做边记）

### 问题 1：词袋向量被高频词稀释
- **现象**：所有问题都命中文档第一个块（含 RAG/AI/API 等高频词）
- **根因**：纯词袋模型下，高频通用词主导余弦相似度
- **解法**：改用 TF-IDF 加权（高频词降权、稀有词升权）
- **验证**："技能"问题相似度 0.865 → 1.000

### 问题 2：overlap 切分产生句边界碎片
- **现象**：块开头出现"块。第四步"这种截断残留
- **根因**：overlap 按字数硬切，切在句子中间
- **解法**：语料句边界规范化（分号/枚举句改句号）+ 切分正则纳入分号

### 已知局限（诚实标注，面试可主动说）
- 词袋+TF-IDF 是"词面匹配"，无法理解"向量化→embedding"这类语义等价
- **这正是真实 RAG 用 embedding 模型的原因**，本项目留作待升级点（接 OpenAI text-embedding 替换词袋）
