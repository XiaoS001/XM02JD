## 一、一句话目标

用 Python + MySQL 从 0 跑通一条「AI 获客」流水线：**模拟数据 → 采集 → 清洗验证 → 分类打分 → 个性化触达 → 转化追踪**，每段产出可复现、可验证的中间结果。

---

## 二、技术决策（已确认）

| 决策 | 选择 | 理由 |
|---|---|---|
| 数据源 | 模拟数据为主 | 安全合规、可复现、不依赖网络；预留真实爬虫接口 |
| 触达 | 本地 mock | 触达动作落库，生成个性化内容但不真发 |
| 技术栈 | Python + MySQL | 数据 pipeline 天然适合 Python；MySQL 存线索库 |

---

## 三、六段 Pipeline 与验收标准（★每段必须机器验证）

| 段 | 做什么 | 验收标准（可机器验证） |
|---|---|---|
| S1 数据源 | 生成模拟企业名录 | 生成 N 条企业记录，含行业/规模/联系方式/网站，落盘 JSON |
| S2 采集 | 采集器从数据源抽取线索 | 从源抽取线索，字段完整，预留真实爬虫接口 |
| S3 清洗验证 | 去重、补全、邮箱格式校验 | 去重后无重复；邮箱格式非法项被标出；补全缺失字段 |
| S4 分类打分 | 按行业/规模/意向给线索分级 | 每条线索得到 A/B/C 等级，分级规则可解释、有统计 |
| S5 触达 | 生成个性化触达内容 + mock 落库 | 每条 A/B 级线索生成个性化话术，落库为触达记录 |
| S6 转化追踪 | 漏斗统计 + 归因 | 输出各阶段转化率漏斗，能定位流失环节 |

**端到端验收**：一条命令跑完 S1→S6，输出完整漏斗 + 各阶段产物落盘。

## 七、问题与解决（边做边记）

### 问题 1：控制台 emoji 导致 GBK 编码崩溃

- **现象**：打印 `✅` 时 `UnicodeEncodeError: 'gbk' codec can't encode character '\u2705'`
- **根因**：Windows 控制台默认 GBK，无法编码 emoji（XM01 经验库 P3 的变体）
- **解法**：① 代码内避免 emoji，用 ASCII 标记；② 运行时加 `PYTHONIOENCODING=utf-8`
- **验证**：修复后 exit 0，全流程正常输出中文

### 运行方式（完整）

```bash
cd 02-项目/P01-AI获客/src
python pipeline.py            # 若中文乱码，加环境变量 PYTHONIOENCODING=utf-8
```
