# HR / 面试官提问台账

> 用途：把每次被问到的问题（以及你预判会被问到的问题）**原文记下来**，逐条准备答案。
> 原则：**记录真实提问的原话**，不要美化。原话能暴露面试官真正在意什么。

---

## 使用方式

1. 每次面试/沟通后，**当天**把被问到的问题补录到下面的表格；
2. 对每个问题标注「准备状态」；
3. 状态为 ⬜ 的，逐条准备答案，答案要**有项目支撑**（能说出代码在哪、怎么验证的）；
4. 准备完成后把答案写到该问题的「我的回答」一栏，并在 `01-求职工作台/02-项目索引/` 里对应到具体项目。

## 二、高频问题分类与准备策略

> 下面是求职中反复出现的几类问题。**即使还没被问到，也应当提前准备**。

### 2.1 项目真实性类（★最容易被问倒）

| 问题 | 准备要点 |
|---|---|
| 以前有没有做过 XXX？ | 必须有可运行代码 + 验证记录。**没有就承认没有，然后说"但我为此做了什么"** |
| 这个项目你负责哪部分？ | 说清楚自己写的模块、代码行数、解决的具体问题 |
| 遇到最大的困难是什么？ | 用 XM01 的"问题与解决"格式：现象 → 根因 → 解法 → 验证 |
| 为什么用这个技术方案？ | 说清对比过哪些方案、为什么选这个 |

### 2.2 技术深度类

| 问题 | 准备要点 |
|---|---|
| 说一下 XXX 的原理 | 能画图讲清楚，不只背概念 |
| XXX 和 YYY 的区别？ | 列对比表，说清适用场景 |
| 如果数据量涨 10 倍会怎样？ | 说清瓶颈在哪、怎么优化 |

### 2.3 工程经验类

| 问题 | 准备要点 |
|---|---|
| 怎么保证代码质量？ | 测试、自检、code review（对应 XM01 的自检脚本实践） |
| 线上出问题怎么排查？ | 日志、监控、复现、定位、修复、回归 |
| 怎么和前端/测试协作？ | 接口约定、联调流程 |

### 2.4 软技能类

| 问题 | 准备要点 |
|---|---|
| 为什么选择我们公司？ | 提前调研公司业务，结合自身方向说 |
| 职业规划是什么？ | 1-3 年做深技术，方向与岗位匹配 |
| 期望薪资？ | 提前查行业水平，给区间不给单点 |

## 三、答案准备模板

针对每个 ⬜ 未准备的问题，按下面结构准备答案：

```markdown
### 问题 N：<提问原文>

**考察点**：
**回答框架**（STAR 或 原理→实践→数据）：

1. 先给结论：
2. 展开说明：
3. 用项目佐证：代码在 `01-求职工作台/03-源码/...`，验证记录在 `01-求职工作台/03-验证与实验/01-验证记录/...`
4. 补充踩坑（加分项）：遇到什么坑、怎么解决的

**可能的追问**：
- 追问 1：→ 准备怎么答
- 追问 2：→ 准备怎么答

**准备状态**：⬜ / 🔄 / ✅
```
